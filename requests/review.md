# Code review, 2026-11-27

Reviewed version `0.8.6` at `545159c`. A Windows rerun passed all 346 automated tests with Cursor's embedded Node 24.22.1. Standalone Node 24.22.3 failed the draft-removal test at the same revision. `extension.js` passed its syntax check. The live Cursor UI scenarios were outside this review. Line references below describe the reviewed revision.

## Data loss and misplaced files

These four P1 findings were reproduced in disposable fixtures.

1. **An unreadable partial copy can delete repository files.** The directory walker returns an empty listing when `readdirSync` throws. After one successful sync, a simulated `EACCES` while listing the copy produced a `deletedInSource` action and removed the original file. A failed listing on the repository side can propagate deletions in the other direction. Preserve the affected subtree and its last known state until a complete scan succeeds. [Directory scan](../lib/materialize.js#L38) · [Deletion decision](../lib/materialize.js#L475)
2. **Push to a branch can erase work saved during the push.** Editors and agents can write to the managed clone after the commit. The window runs from the pushed snapshot through the final reset and clean, so it includes the network push. With real local Git operations and a simulated successful network push, a tracked edit was reverted and a newly created file disappeared during cleanup. The command reported success. Cleanup must preserve work created after the pushed snapshot. [Post-push cleanup](../lib/contribute.js#L177)
3. **Renaming a root-level plugin moves the checkout.** A marketplace entry with `source: "."` loads the repository root as the plugin directory. Rename returned success and moved the checkout's contents to a sibling directory, leaving the configured path without its files. Decide whether to rename only the plugin metadata or decline this operation before any write. [Destination](../lib/rename.js#L238) · [Directory move](../lib/rename.js#L297)
4. **A stale conflict choice can overwrite a newer edit.** The dialog checks the window's cached conflict list. Under the lock, the resolver checks only the manifest version. After resolving a conflict and making a newer repository edit, replaying the other window's pending choice overwrote that edit. Under the lock, verify that the conflict still exists and that its two versions match the ones presented to the user. [Dialog](../extension.js#L3187) · [Resolver](../lib/materialize.js#L509)

## Other correctness and security findings

| Priority | Finding and evidence |
|---|---|
| P1 | **New plugin and Move draft can write outside the target repository.** Authoring uses `metadata.pluginRoot` to build a destination without checking that it resolves inside the checkout. Move can then delete the draft after copying it to a location the catalog will reject. Validate the destination before copying or deleting. [Authoring destination](../lib/authoring.js#L244) |
| P1 | **Git output can expose repository credentials.** Logging the raw command arguments and stderr can put a token from an HTTPS clone or fetch URL into the Team Plugins log. Redact credentials wherever URLs are included in diagnostics. The project settings writer already handles the same kind of URL. [Git logger](../lib/sync.js#L241) · [Settings redaction](../lib/repos.js#L451) |
| P2 | **A failed unregister is forgotten.** With an API that rejected removal, the registrar listed the path as both removed and failed, then made no removal attempt on the next apply. A disabled plugin can stay active. Keep failed removals in the registration map so they can be retried. [Registrar](../lib/registrar.js#L25) |
| P2 | **Add and Rename cannot reliably edit valid MCP files.** The catalog reads JSONC. Add rejected a fixture with a comment and trailing comma, and Rename skips files its strict JSON reader cannot parse. Use consistent MCP parsing and preserve comments when editing. [Catalog](../lib/catalog.js#L310) · [Add](../lib/authoring.js#L205) · [Rename](../lib/rename.js#L140) |
| P2 | **An uncommitted deletion can appear in What changed.** The item list comes from the working tree and the fingerprints come from Git. With a previously seen item absent from the working list, the comparison reported it as removed even though HEAD had not changed. Derive removal evidence from the committed revision. [Item collection](../extension.js#L976) · [Removal detection](../lib/updates.js#L204) |
| P2 | **A failed pre-push check gives permission to push.** An exception while collecting paths or checking the catalog is logged and returns the same success value as a clean check. Surface the failure so the user gets the explicit choice to proceed. [Pre-push check](../extension.js#L3338) |
| P2 | **Two windows can lose each other's seen marks.** Both can read the same record, acknowledge different items, then replace the entire record. They also share one temporary filename. Serialize the read, merge and write for each repository, and give each write a unique temporary file. [Mark seen](../extension.js#L1104) · [Record writer](../lib/updates.js#L246) |
| P2 | **The remote diagnostic helper's archive check accepts sibling paths with the same prefix.** The helper checks path strings with `startswith` before extraction. Check containment by path components and accept only the expected regular files and directories. [Archive extraction](../scripts/live_check.py#L248) |
| P3 | **A generated skill can immediately fail its own description check.** Giving the scaffolder the description `2026-11-27` produced an unquoted YAML date and the diagnostic “No description”. Quoting user-provided descriptions would also handle values such as `true` and `null`. [YAML writer](../lib/authoring.js#L41) |

## Code smells and duplication

- **The operation queue makes failures look like cancellations.** `enqueue` catches exceptions and resolves with `undefined`, which several command handlers also use for a cancelled operation. Recover the queue for subsequent commands while letting the current caller report its failure. [Queue](../extension.js#L333)
- **Move and Rename duplicate the settings migration.** Both transform the same enabled and excluded ID lists, compare the serialized values, and update global settings. This is a small extraction with two concrete callers in the roughly 3,900-line extension entry point. [Move](../extension.js#L2567) · [Rename](../extension.js#L2680)
- **Refresh repeats synchronous reads and parsing on the extension host.** Each apply rereads eligible catalogs. For each skill or rule, diagnostics and context estimation separately parse and lint the same frontmatter. Reuse the parse result and measure refresh time on a large catalog before attempting a broader refactor. [Refresh](../extension.js#L649) · [Per-item work](../lib/catalog.js#L212)
